# UI 审计基线（2026-10）

> 模式：ui-design **extract** — 把现状逆向成可对照的基线，不是背书。
> 方法：`packages/app` 源码 + `npm run ui-walkthrough` 截图（本地 `ui-walkthrough-shots/`，不入库）
> + 逐对计算对比度。所有 hex 均从 token 或源码读取，不靠目测。

## 结论

当前 UI 的主问题是**执行不一致**，不是缺少某个流行样式：视觉语言整体来自 Paseo 移植
（ADR-0005），Pie 只换了主色；同一语义有多套实现；导航有三层重复入口。结果是在
1440px 下界面发灰、层级靠 1px 线和 10px 小字维持，识别度与可读性一起丢失。

## 矛盾清单

1. **四套选中态**：topbar 图标 = accent 填充；inspector rail tab = surface2 + 白图标（1.2:1）；workspace tab = surface2 + hairline；聚焦 pane = 2px accent 底线。
2. **两套导航模型**：workspace tab 与 inspector rail 同时提供 Files/Changes，二者互不知道对方状态。
3. **三个新会话入口**：侧栏行、`New session` 常驻 tab、tab 行尾 `+`（后两者调用同一 `openNew`）。
4. **两套视觉语言**：app 浅色（`#FFFFFF/#2B4C7E`）与 daemon 演示页暗色（`#101216/#6EA8FE`）。
5. **两套运行态**：dark theme 注册但被 `_layout.tsx:105` 强制切回 light；`accentBright` 在浅色下等于 `accent`。
6. **布局常量两份**：`constants/layout.ts` 的 `SIDEBAR_WIDTH=200` 未被使用，实际宽度 232 写在 `app-container.tsx:26`。
7. **语言边界**：daemon 硬编码中文会话占位 `"（新会话，未落盘）"`，en UI 下直接显示中文。

## 可保留的部分

- 三栏骨架（会话栏 / 主区 / 检查器）本身是对的，问题是每栏的入口与选中语汇没有收敛。
- token 底座（unistyles + 语义色 + 密度系统）已经存在，重构不需要换技术栈。
- 验证链（`verify-pie` + `ui-walkthrough`）能真实驱动 UI，视觉改动可以被证明而不是口头声明。
