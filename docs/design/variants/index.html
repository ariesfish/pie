这一版改了什么

  • 导航收成两层：侧栏管会话；主区 tab 管内容；检查器是主区的上下文，不再和 tab 平级抢入口。
  • 去掉常驻「新会话」tab：它和 + 调用同一个动作。只留 +，新会话直接落在空会话面。
  • 选中态一套语汇：背景抬升 + 字色加深；强调色只给主操作、运行状态和链接。
  • 字号回到 12 起步：会话行 13、正文 15、标题 20；不再用 10px 小字撑密度。
  • 表面阶梯可辨：canvas / sub / raise 三档，细线只做收边，不独自承担结构。
  • 移动端同构：同样的三层信息，抽屉退化为顶部 + 手势，不引入第二套导航语汇。

方案差异

A · quiet-saas（已选）：中性纸面、墨字、蓝紫单强调色。 最接近专业工具，跨端最稳；识别度靠克制与精确，不靠装饰。

B · 暖纸（claude 系，未采用）：米白纸、衬线标题、陶土强调色。 阅读感和人味更强，和 IDE 类客户端拉开距离；代码/diff 仍走中性纸面。

色彩（当前方案）

对比度为实测值（前景 / 实际底色）。正文小字门槛 4.5:1。

导航收敛

之前侧栏 + 三层 tab + 5 模式 rail 之后侧栏 + 内容 tab + 上下文检查器 入口会话 / 文件 / 变更 / 用量各一个主入口 选中抬升 + 字色；强调色只做操作与状态

落地前提

  • 方案选定后写根 DESIGN.md，token 落 packages/app/src/styles/theme.ts。
  • 暖色方案若保留衬线标题，需要随包字体或明确的系统衬线降级清单。
  • 两套都遵守 docs/CONSTRAINTS.md 的 D1–D7；对比度按实测，不看截图感觉。
  • 改动顺序：先修缺陷 → 再换 token → 最后收导航，每步可单独回滚。
